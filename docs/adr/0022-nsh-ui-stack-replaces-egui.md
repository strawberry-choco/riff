# The nsh UI Stack Replaces egui, Behind a Second Binary Until Parity

**Status**: Accepted
**Date**: 2026-11-20

riff replaces its egui frontend with the nsh UI stack. The rewrite is presentation only: the five backend crates, their ports, sessions and channels stay untouched. It ships as a second binary, `riff-nsh`, beside `riff` until feature parity at N15, and then the three egui crates — `riff-gui`, `riff-gui-components` and `riff-gui-theme` — are deleted. Pixel parity is out of scope; feature parity is the bar. The unit-by-unit plan is `docs/execution-plans/nsh-ui-rewrite.md`, and the decision rests on the P0 feasibility spike's conditional go (`docs/execution-plans/evidence/nsh/p0/memo.md`): the bridge, the 50k-row list and covers ran against the real backend, and chrome, keyboard input, runtime palette switching and folder drop were proven on Windows.

N1 is the scaffold this ADR lands with: a window showing the riff name and a version line, no store read, no backend edge, no palette port. Those belong to N2 (the theme port), N3 (the backend bridge) and N4 (the shell). From N1 the egui frontend is feature-frozen — bug fixes only, new behavior lands in nsh first — so the two stacks cannot drift apart while both exist.

## Considered Options

- **In-place rewrite on a branch.** egui and nsh cannot share a window, so every intermediate commit is an app that does not run: no shippable state for the whole rewrite.
- **Big bang in one PR.** No intermediate evidence and no way to isolate a regression.
- **TSX or mixed mode.** A JavaScript VM, a second language and a split type boundary, for hot reload alone; nsh's docs recommend Rust mode for large business logic, and riff's is large.
- **egui and nsh in one window.** One event loop per toolkit.
- **Restyle egui and call it the rewrite.** Does not meet the goal.

## Consequences

- **The workspace gains a tenth member and a second binary.** `riff-gui-nsh` produces `riff-nsh`; the release pipeline still builds and ships only `riff` until N16. The lock grows from 658 to 798 packages: 115 added, 24 duplicate coexistences where an old version survives beside a new one, and 6 replacements, none in the golden render path. No feature edge changed in the four captured feature trees (`riff-gui`, `riff-gui-components`, `riff-gui-theme`, `riff-tests`) — the only tree differences are the `cc` and `find-msvc-tools` build-tool versions. The evidence is `docs/execution-plans/evidence/nsh/n1/lock-diff.txt` and `docs/execution-plans/evidence/nsh/n1/feature-tree-diff.txt`.
- **All seven framework crates pin at `=0.6.1`.** The plan's block pinned `nsh-core` at `=0.6.0` against six at `0.6.1`; that set is misaligned, and 0.6.1 supersedes it (P0 memo, Version alignment). nsh makes no compatibility promise for its Rust crates, so the pin is exact and the set moves as one.
- **The platform feature list is trimmed to `["shader", "svg"]`, identical on all three OSes.** Everything the generated template enables beyond these two is a component riff never renders or a network stack an offline-first player must not carry. `nsh-base` and `nsh-engine` carry `default-features = false` in the root workspace block, and that is load-bearing: `nsh-base`'s default is `editor, highlight, plot, rich-editor, term`, and `nsh-engine`'s default is `js`, which pulls QuickJS through `nsh-js`. Feature unification is a workspace-wide union, so inheriting either with defaults on re-adds what the platform lists trim — the generated template's "minimal" lock still carries `syntect` and `two-face` for exactly this reason.
- **The memo's wgpu claim is corrected.** wgpu is gated by `shader`; both P0 graphs kept `shader`, which is why wgpu survived trimming in both. Keeping it costs zero new packages: wgpu, naga and pollster are already locked at these versions for `egui_kittest`. The memo's "hard dependency of `nsh-engine`, not feature-gated" reading (correction 8) is superseded.
- **Resolver 2 stays.** Resolver 3's MSRV-aware resolution can select older-than-newest versions and re-resolve the existing members' lock entries, and the egui golden baselines are byte-exact for one patch level of egui, eframe and `egui_kittest` and the wgpu and naga pair they rasterise through — lock churn is a golden-test risk, not just a build risk. Resolver 2 already does the per-target feature unification the nsh graph relies on. Revisit only with a measured lock diff and a green golden suite.
- **The MSRV moves from 1.95 to 1.97.** The nsh crates declare `rust-version = "1.97"`, so the floor is the framework's. The string lives in six declarations — `[workspace.package]`, `clippy.toml`, `AGENTS.md`, `docs/engineering/development-setup.md`, `CONTRIBUTING.md` and the `ci.yml` MSRV comment — and all six move together. CI's exact toolchain pin is separate and unchanged.
- **The egui three keep their token authority through the coexistence window.** `crates/riff-gui-theme/src/theme.rs` remains the store and the read source for `riff-gui-theme`, `riff-gui-components` and `riff-gui`, with their three per-crate sweeps (ADR 0004's 2026-10-15 amendment). `riff-gui-nsh` reads nsh `Tokens` through `theme()` and, from N2, its own `Signal<Palette>`. ADR 0004 gains the coexistence amendment at N1; N2 appends the store-naming one. `theme.json` restyles `nsh_base` controls only and is never the riff palette's store.
- **`theme.json` exists at N1, wired rather than inert.** It ships as identity plus empty `cssVars` maps, and `main.rs` passes it through `Root::of::<App>().tokens(...)`: the generated bootstrap reads no theme file on the `cargo run` path, so without that wiring the file does nothing. `nsh_base::tokens_of` clones the defaults and applies the file leniently, so the empty maps are safe. N2 fills them.
- **The Windows subsystem attribute is release-only.** `#![cfg_attr(all(target_os = "windows", not(debug_assertions)), windows_subsystem = "windows")]` — the inner-attribute convention copied from `crates/riff-gui/src/main.rs:22`, so debug builds keep the console and logs stay visible. The `cfg_attr` only fires in release, so a green debug clippy gate is not evidence the attribute is well-formed; a local Windows release build is mandatory N1 evidence.
- **No nsh CLI in CI until N16.** `cargo run`, `cargo build` and `cargo test` are the whole N1 loop; the CLI's first consumer is N16's packaging. CI gains a `cargo build --locked --workspace --bins` link step instead, because clippy and test do not link a shipped executable — and being debug, it does not exercise the release-only subsystem attribute either.
- **N1 is fenced by four scaffold tests.** They pin the brand asset in the registry, `nsh.json`'s agreement with the bootstrap constants, the manifest fence (no egui token, no `riff-*` token outside `riff-backend`, no `[profile.*]` table), and the theme wiring on `Root`. The `riff-backend` edge arrives at N3 with the first `use riff_backend::`; the fence's allowlist already permits it. The brand PNG ships at N1, extracted from the 1024x1024 chunk of `riff.icns` by a committed tool.
- **One logging init, matching `riff-gui`.** `tracing_subscriber::fmt::init()` already installs the `log` bridge (`tracing-log` is in its default features), so nsh's `log` records surface through it; a second explicit `LogTracer::init()` would panic at startup. `color_eyre::install()` stays, as in `crates/riff-gui/src/main.rs:31`. The template's `env_logger` would be a second logging stack and a new lock entry.
